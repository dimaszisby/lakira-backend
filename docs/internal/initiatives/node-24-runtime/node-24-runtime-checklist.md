## Phase 3 — verify on a real Node 24

The host runs Node 26.5, so a Node 24 binary is fetched into the session scratchpad and put
first on `PATH` for every gate.

- [x] `node -v` prints `v24.21.0` for the gate runs (tarball checksum-verified against
      `SHASUMS256.txt`)
- [x] `npm run jest -- --listTests` starts on 24. That script passes
      `--es-module-specifier-resolution=node`, which Node removed in 19; fix it only if 24 rejects it.
      Result: 24 accepts the flag silently and lists 123 test files, so no fix
- [x] `npm run docker:build` builds on `node:24-alpine` (image reports `v24.21.0`, npm `11.19.0`)
- [x] `bcrypt` loads and hashes inside the built image (`$2b$04$…`, from the musl prebuild)
- [x] The image, started on the dev Compose network, answers `/api/v1/health` and `/api/v1/ready`
      with 200, completes a register-then-login round trip, and logs it with a request id
      (AsyncLocalStorage, ADR-0027, runs on AsyncContextFrame from Node 24). Result: health 200,
      ready 200, register 201, login 200 with the refresh cookie, profile 200. The register request
      id appears on the `[EMAIL:CONSOLE]` line, written after the awaited DB work
