## 1. Verdict

**GOLD WITH CAVEATS (reconfirmed) — clean GOLD blocked by C1.**

The strict ADR-001 fork-ready gate **passes**: zero P0; the six ADR-001 gates are green on Node 24;
all six gated categories are at or above 80%; `LICENSE` and `.env.example` are present. No
exploitable security hole or cross-tenant exposure was found. The 06-05 P0s (N1, N2) and the F1
high are confirmed closed in code.

ADR-008's condition for clean GOLD is that C1–C6 are closed. At HEAD they are not:

- **C1 (P1) is not closed.** A fresh fork's printed step 4, `npm test`, fails at integration.
  `bootstrap-fork.sh` renames the database credentials in `.env` but not in `.env.test`, so the
  suite logs in as a role the fork's database never creates. Reproduced against a throwaway
  Postgres with the fork's own settings (§5). It is invisible on any machine already running the
  Lakira stack, which is how it survived the closure.
- **C3 and C4 (P2) closed narrower than claimed.** The envelope still has HTML 404s and masked
  500s for client errors (reproduced), and the feature-boundary rule accepts audience-prefixed
  deep imports (reproduced with ESLint; 9 live instances).
- **C2, C5, C6 are confirmed closed.**

The remaining work is small. The C1 fix is under a day. With C1 fixed, a later dated run can
restate GOLD. C3 and C4 would then be caveats again, at P2, unless they are fixed first.

## 9. Risk-ranked recommendations

1. **Close C1** (≤1d). Rename the test credentials in `bootstrap-fork.sh` too, or derive them
   from `.env`. Build database identifiers from the short name with hyphens replaced (the
   tutorial's own `my-app` gives an invalid unquoted `my-app_test_db`). Add `db:migrate:test` and
   RabbitMQ to the printed steps and the tutorial. Add a CI job that runs bootstrap on an exported
   tree and then `npm test`, which is the only way this class of break gets caught.
2. **Then a dated run to restate GOLD**, if C1 holds on a fork.
3. **C3 and C4 residuals** (≤1d each): a JSON 404, client-error mapping for body-parser errors,
   limiters through `sendError` (the 429 schema change touches lakira-frontend's types, so it needs
   an ADR); audience-aware boundary patterns with persisted negative tests.
4. **R1** and **R2** (≤1h each), since R2 serves wrong results.
5. **R3** (≤1d): drainable background work, which also closes the `TRUNCATE` flake.
6. **R6**: build and smoke the image in CI before ADR-0042's VPS work, and correct its status.
7. Everything else as tracked.
