## Verdict (one paragraph)

Lakira is **not fork-ready as a SaaS base today**. Empirical static and test gates are all green, the DDD feature-slice architecture is consistently applied for the auth + core CRUD slices, and the security/observability primitives (helmet, hpp, xss-clean, three-tier rate limiter, Winston JSON logging, central error handler, OpenAPI gen + Swagger UI, security-delta CI gate) are all wired. But the repo is missing the public-base scaffolding that a forker needs on day one — no `README.md`, no `LICENSE` despite `package.json` declaring ISC, no `.env.example` covering the full env surface, no refresh-token flow, no email verification, no multi-tenancy primitives, no request-ID propagation, no `trust proxy` setting (which silently breaks IP-based rate limiting on Render), and a roughly 13-file Lakira-branding footprint with no rename script. There is also moderate architectural drift inside the metric\* feature slices (duplicate `MetricAccessSequelize` adapters, two "transaction" ports in metric, mappers split across two locations, analytics has no domain entities and uses raw SQL) which a forker would inherit.

## 1. Authentication & Authorization

### [P0] 1. Authentication · No refresh-token flow

- **Status:** Missing
- **What's missing/incomplete:** JWTs are signed with `expiresIn: "7d"` and there is no `/auth/refresh` route, no `RefreshToken` entity, and no rotation/revocation. `POST /api/v1/auth/logout` returns 200 without invalidating the token (`controller.ts:97-99`).
- **Why it matters for a SaaS base:** A 7-day non-rotating bearer token is a long-window credential. SaaS bases typically pair a 15-min access token with a rotating refresh token stored as an HttpOnly cookie. Without it, every fork inherits a broad XSS/token-leak blast radius and a useless logout.
- **Recommended fix:** Add a `RefreshToken` entity (id, userId, hashedToken, expiresAt, revokedAt, createdAt, replacedById) + `RefreshTokenRepository`. Issue refresh as HttpOnly cookie on login; rotate-and-revoke on `/auth/refresh`; revoke on `/auth/logout`. Reduce access-token TTL to 15 min. Drop the inline `jwt.verify` from `authMiddleware.ts:42` and route all token ops through `TokenProvider` (extend the port with `verify()` and `signRefresh()`).
- **Effort:** L
- **Evidence:** `src/features/shared/auth/infrastructure/providers/JwtTokenProvider.ts:11`; `src/features/shared/auth/infrastructure/http/authMiddleware.ts:42`; `src/features/shared/auth/infrastructure/http/controller.ts:97-99`; no `refresh_token*` migration in `src/migrations/`.

### [P1] 1. Authentication · No email verification

- **Status:** Missing
- **What's missing/incomplete:** No `email_verified_at` column on `users`, no `EmailVerificationToken` entity, no `/auth/verify-email` or `/auth/resend-verification` route. New users immediately have a usable account.
- **Why it matters for a SaaS base:** Forkers ship with verified-email assumptions baked into downstream flows (billing, password reset, abuse handling). Adding it post-hoc requires backfill migrations.
- **Recommended fix:** Mirror the `PasswordResetToken` pattern. Add `email_verified_at` to `users`, an `EmailVerificationToken` entity + repo, and gate sensitive endpoints behind `requireVerifiedEmail`. Reuse `EmailSender` port + `ResendEmailSender`.
- **Effort:** M
- **Evidence:** `src/features/shared/auth/infrastructure/persistence/models/user.sequelize.ts` (no `emailVerifiedAt`); no matching migration in `src/migrations/`.

### [P1] 1. Authorization · RBAC is a stub

- **Status:** Partial
- **What's missing/incomplete:** `User.role` is a `"user" | "admin"` enum and `requireAdmin` middleware exists, but it is wired only to `GET /api/v1/admin/_ping` (`server.ts:127`). There is no permission system, no role table, no role-to-route policy map.
- **Why it matters for a SaaS base:** Most SaaS forks need at least owner/admin/member granularity per workspace; an enum on `users` cannot represent that.
- **Recommended fix:** Defer until the multi-tenancy P0 lands (see 9). Then introduce `Role`, `Permission`, and `Membership(userId, organizationId, role)` and a thin `requirePermission("scope:action")` middleware. For pre-tenant base, at minimum keep the enum but add `assertAdmin(req)` helper symmetric to `assertAuthenticated(req)`.
- **Effort:** M
- **Evidence:** `src/features/shared/auth/infrastructure/persistence/models/user.sequelize.ts:65-69`; `src/features/shared/auth/infrastructure/http/requireAdmin.ts`; `src/server.ts:126-131`.

### [P2] 1. Authentication · No OAuth / social login

- **Status:** Missing
- **What's missing/incomplete:** No Passport, no `@auth/express`, no Google/GitHub/Apple integration.
- **Why it matters for a SaaS base:** Many forks expect OAuth on day one; lack of it isn't a blocker but is friction.
- **Recommended fix:** Add `@auth/express` (Auth.js for Express) once refresh tokens land — they share the cookie session model. Wire one provider (Google) end-to-end as a reference.
- **Effort:** L
- **Evidence:** `package.json` deps — no oauth/passport packages.

## 2. API Design & Contracts

### [P1] 2. API · Response envelope inconsistency between success and validation-error paths

- **Status:** Partial
- **What's missing/incomplete:** Success responses use `{ status, message, data, success, code? }` (`src/utils/response-formatter.ts:35-49`). Validation failures and malformed JSON return a different shape from `errorHandler`: `{ status: "fail", errors: [{ field, message }] }` — no `data`, no `success`, no `message`.
- **Why it matters for a SaaS base:** Frontend consumers and contract tests have to branch on shape. The OpenAPI spec exposes both shapes, doubling client-side handling.
- **Recommended fix:** Normalize the error envelope to `{ status: "error", message, data: null, success: false, errors? }` so all responses share the top-level keys. Update `errorHandler` and the contract test fixtures in lockstep. Regenerate OpenAPI.
- **Effort:** S
- **Evidence:** `src/shared/middleware/error.ts:30-48`; `src/utils/response-formatter.ts:35-49`.

### [P2] 2. API · No shared pagination type / helper

- **Status:** Partial
- **What's missing/incomplete:** Cursor pagination is reimplemented per feature with subtle drift: `metric` returns `{ items, nextCursor, sort, limit, q?, filter?, totalCount? }`, `metric-settings` returns a slightly different shape via `ListMetricSettingsViaCursor`. There is no `Page<T>` type in `src/shared/`.
- **Why it matters for a SaaS base:** Forkers will keep duplicating the cursor logic per feature; the OpenAPI surface stays subtly inconsistent.
- **Recommended fix:** Add `src/shared/pagination/Page.ts` with a generic `Page<T>` and `parseCursorQuery()` helper. Migrate features incrementally. Add Zod schema for cursor query and reuse via `extendZodWithOpenApi`.
- **Effort:** M
- **Evidence:** `src/features/public/metric/application/queries/ListMetrics.ts`; `src/features/public/metric-log/application/queries/ListMetricLogs.ts`; `src/features/public/metric-settings/application/queries/ListMetricSettingsViaCursor.ts`.

## 3. Database Layer

### [P0] 3. Database · No multi-tenancy primitives

- **Status:** Missing
- **What's missing/incomplete:** Zero matches for `tenant`, `workspace`, `account_id`, `organization_id` across the codebase. Every domain table has `user_id` but no higher unit of isolation.
- **Why it matters for a SaaS base:** Most non-trivial SaaS apps need at least an `Organization` (or `Workspace`) so a single user can belong to multiple billing units. Retrofitting it after launch requires backfill of every domain table.
- **Recommended fix:** Decide the model up front: (a) "personal-only" — keep `user_id` as the boundary and document explicitly that the base is single-tenant-per-user; or (b) introduce `Organization` + `Membership(userId, organizationId, role)` and add `organizationId` to all domain tables now. For a forkable SaaS base, (b) is the right call. Add `organizationId` to all current models in a pre-data migration; require `req.organizationId` to be derived from membership in `authMiddleware`.
- **Effort:** L
- **Evidence:** No matches for `tenant|workspace|organization_id|account_id` in `src/`.

### [P1] 3. Database · Inconsistent soft-delete policy

- **Status:** Partial
- **What's missing/incomplete:** `paranoid: true` is set on `User`, `MetricCategory`, `Metric` only. `MetricSettings`, `MetricLog`, `PasswordResetToken`, and `processed_messages` are hard-deleted.
- **Why it matters for a SaaS base:** Any compliance story (GDPR right-to-erasure with audit trail, undo for end-users) needs a uniform policy. Mixed mode confuses forkers and creates referential-integrity surprises (a soft-deleted Metric leaves orphaned hard-deleted MetricLogs).
- **Recommended fix:** Pick a policy and document it in `decisions.md`. Probable choice: paranoid on user-owned domain rows (`MetricSettings`, `MetricLog`); hard-delete on system rows (`PasswordResetToken`, `processed_messages`, future `RefreshToken`). Add migrations to add `deleted_at`. Update mappers to filter `deletedAt IS NULL` consistently.
- **Effort:** M
- **Evidence:** `src/features/shared/auth/infrastructure/persistence/models/user.sequelize.ts:84`; `src/features/public/metric/infrastructure/persistence/models/metric.sequelize.ts:97`; `src/features/public/metric-category/infrastructure/persistence/models/metric-category.sequelize.ts:90`; `src/features/public/metric-log/infrastructure/persistence/models/metric-log.sequelize.ts` (no paranoid); `src/features/public/metric-settings/infrastructure/persistence/models/metric-settings.sequelize.ts` (no paranoid).

### [P2] 3. Database · No general-purpose dev/test seed scripts

- **Status:** Partial
- **What's missing/incomplete:** `src/seeders/` does not exist. The only seed is `scripts/seed-contract-tests.ts` (creates a single user + sample metric data for contract tests). No `npm run db:seed:dev`.
- **Why it matters for a SaaS base:** Forkers cloning the repo cannot get a populated dev DB without writing fixtures.
- **Recommended fix:** Add `src/seeders/dev/` with the existing test users + a generic "demo workspace" once tenancy lands. Wire `npm run db:seed:dev` and document it in `README.md`.
- **Effort:** S
- **Evidence:** `scripts/seed-contract-tests.ts`; `.sequelizerc` has commented-out `seeders-path`.

## 4. Security

### [P0] 4. Security · No `trust proxy` / HTTPS readiness

- **Status:** Missing
- **What's missing/incomplete:** `app.set("trust proxy", ...)` is never called in `src/server.ts`. There is no HTTPS-redirect middleware. The CI/CD strategy (`docs/reference/ci-pipeline/strategy.md`) targets Render — a reverse-proxied PaaS — meaning `req.ip` returns the proxy's IP, breaking IP-based rate limiting (`globalRateLimiter`, `passwordResetIpRateLimiter`) and IP logging.
- **Why it matters for a SaaS base:** This is a silent security regression: the rate limiter still "works", but every request is grouped under the proxy IP, so a bad actor effectively shares a single bucket with all legitimate users.
- **Recommended fix:** In `src/server.ts`, after `const app = express()`, add `app.set("trust proxy", env.TRUST_PROXY ?? 1)`. Add `TRUST_PROXY` to `zodEnv.ts` (`z.coerce.number().or(z.literal("loopback")).optional()`). Set to `1` in `.env.production`/`.env.staging`. Add an HTTPS-redirect middleware guarded by `NODE_ENV === "production"` that uses `req.secure` and `req.get("x-forwarded-proto")`.
- **Effort:** S
- **Evidence:** `grep -n "trust proxy" src/server.ts` — no match.

### [P1] 4. Security · 7 environment reads bypass `envManager` (analytics feature)

- **Status:** Partial
- **What's missing/incomplete:** The analytics feature reads `process.env.VIZ_*` and `process.env.DEFAULT_TZ` directly in 6 files, untyped and unvalidated, contradicting `.claude/rules/environment.md` ("All environment access goes through `loadEnvOrExit()`").
- **Why it matters for a SaaS base:** Forkers inherit invisible env knobs. A typo in a Render dashboard silently produces wrong defaults.
- **Recommended fix:** Add `VIZ_MAX_BUCKETS`, `VIZ_DASH_MAX_METRICS`, `VIZ_DEFAULT_TTL_SEC`, `VIZ_CACHE_MAX_AGE_SEC`, `VIZ_CACHE_STALE_SEC`, `VIZ_FALLBACK_GUARD_BUCKETS`, `DEFAULT_TZ` to `src/config/zodEnv.ts` with explicit defaults and units. Replace each `process.env.X` read with `loadEnvOrExit().X`.
- **Effort:** S
- **Evidence:** `src/features/public/analytics/application/queries/GetDashboardVisualization.ts:23,36`; `…/GetVisualization.ts:20`; `…/infrastructure/cache/VisualizationCacheRedis.ts:11`; `…/infrastructure/http/controller.ts:9,11`; `…/infrastructure/http/validators.ts:4,7`; `…/infrastructure/persistence/VisualizationReadRepoSequelize.ts:322`.

### [P1] 4. Security · Winston has no log-redaction filter

- **Status:** Partial
- **What's missing/incomplete:** `.claude/rules/security.md` says env vars matching `/(password|secret|token|key|certificate|url)$/i` are masked. That mask is applied **only** to `maskedEnvSnapshot()` in env-validation failure logs (`src/config/envManager.ts:6`). General Winston logs are not filtered — a `logger.error("login failed", { body })` would print the password.
- **Why it matters for a SaaS base:** Logs frequently end up shipped to a third-party aggregator. Inheriting an unredacted logger means inheriting a future incident.
- **Recommended fix:** Add a Winston `format()` redactor in `src/utils/logger.ts` that walks log meta and replaces values for keys matching the existing `SENSITIVE_KEY_PATTERN` (move the regex out of `envManager.ts` into `src/config/sensitive-keys.ts` for reuse). Add a unit test asserting redaction.
- **Effort:** S
- **Evidence:** `src/config/envManager.ts:6`; `src/utils/logger.ts` (no redaction format).

### [P1] 4. Security · No account lockout / brute-force protection on auth

- **Status:** Partial
- **What's missing/incomplete:** Login is protected by `userRateLimiter` (50 / 15min) only. There is no per-account failed-attempt counter, no account lock, no exponential backoff. `express-brute` is not installed.
- **Why it matters for a SaaS base:** A distributed credential-stuffing attack against 1000 known emails (each at <50 attempts/15min) is undetected.
- **Recommended fix:** Add a per-email Redis counter on failed login (`auth:lockout:<emailHash>`) with sliding window. After N failures, return 429 + a 15-min cooldown. Reset on success. Logging: emit a structured `auth.lockout.triggered` event.
- **Effort:** S
- **Evidence:** `src/features/shared/auth/infrastructure/http/router.ts` — no lockout middleware; `src/shared/middleware/rate-limiter.ts` — no per-account limiter.

### [P2] 4. Security · CORS supports a single origin only

- **Status:** Partial
- **What's missing/incomplete:** `CORS_ORIGIN` is read as a single string (`server.ts:96`); a multi-frontend SaaS (web + admin + mobile-debug) needs a list.
- **Why it matters for a SaaS base:** Most forks add a second origin within weeks; the current code requires a code change.
- **Recommended fix:** Parse `CORS_ORIGIN` as comma-separated; match `origin` against the allowlist. Or accept a regex.
- **Effort:** S
- **Evidence:** `src/server.ts:96-102`.

### [P2] 4. Security · `xss-clean` is unmaintained

- **Status:** Partial
- **What's missing/incomplete:** `xss-clean` (npm) was deprecated in 2022. It still functions but receives no security updates.
- **Why it matters for a SaaS base:** Forkers inheriting an unmaintained dep stays an audit finding indefinitely.
- **Recommended fix:** Replace with output-encoding (escape on render, not on input) — but that's a frontend concern. As a backend mitigation, adopt `dompurify` only where HTML is stored (none today), and remove `xss-clean` once no path stores HTML.
- **Effort:** M
- **Evidence:** `package.json` deps; `src/server.ts:89`.

## 5. Error Handling & Observability

### [P0] 5. Observability · No request-ID / correlation-ID propagation

- **Status:** Missing
- **What's missing/incomplete:** No `cls-rtracer`, `nanoid`, or `req.id` middleware. Logs cannot be correlated to a single request across the app + worker.
- **Why it matters for a SaaS base:** First production incident at any fork hits this wall — there's no way to filter logs to "what happened to request X". Adding it later requires touching every log call site that wants the ID.
- **Recommended fix:** Add a tiny middleware in `src/shared/middleware/request-id.ts`: read `x-request-id` header; if absent, mint `crypto.randomUUID()`; set `req.id`; echo back in response header; and seed a `cls-hooked` async-context (or use AsyncLocalStorage directly). Update Winston format to inject `requestId` from ALS.
- **Effort:** S
- **Evidence:** `grep -nE "requestId|correlationId|cls-rtracer" src/` — no matches.

### [P1] 5. Observability · No external error-monitoring hook point (Sentry)

- **Status:** Missing
- **What's missing/incomplete:** No `@sentry/node` import, no init in `src/server.ts`, no `Sentry.captureException` in the error handler.
- **Why it matters for a SaaS base:** Forkers want a single env-var-driven on-switch for production error tracking.
- **Recommended fix:** Add `@sentry/node` as an optional dep gated by `SENTRY_DSN` env. Init at top of `src/server.ts`. In `errorHandler`, call `Sentry.captureException(err)` for 5xx only. Add `SENTRY_DSN`, `SENTRY_TRACES_SAMPLE_RATE` to `zodEnv.ts`.
- **Effort:** S
- **Evidence:** `package.json` deps — no `@sentry/*`.

### [P1] 5. Observability · `/api/v1/health` is a liveness probe, not readiness

- **Status:** Partial
- **What's missing/incomplete:** `GET /api/v1/health` returns `{ status: "ok", environment, timestamp }` (`server.ts:105-111`). It does not ping Postgres or Redis. There is no `/healthz` or `/ready` endpoint.
- **Why it matters for a SaaS base:** Render and similar PaaS use the health endpoint to gate traffic; a green `/health` while the DB is down means traffic is routed to a broken instance.
- **Recommended fix:** Keep `/health` as liveness (no deps). Add `/ready` that runs `sequelize.authenticate()` + `redis.ping()` (with a 2s budget) and returns 503 on failure. Configure Render to use `/ready`.
- **Effort:** S
- **Evidence:** `src/server.ts:105-111`.

### [P2] 5. Observability · No metrics / APM readiness

- **Status:** Missing
- **What's missing/incomplete:** No `prom-client`, no OpenTelemetry, no statsd. No `/metrics` endpoint.
- **Why it matters for a SaaS base:** Nice-to-have, not blocking. Most forks add APM later.
- **Recommended fix:** Add `prom-client` with default Node metrics + an HTTP histogram middleware. Expose `/metrics` gated by an internal IP allowlist or a shared secret header. Document in README.
- **Effort:** M
- **Evidence:** `package.json` deps — no `prom-client`/`@opentelemetry/*`.

## 10. Code Architecture & Maintainability

### [P1] 10. Architecture · DDD layout drift across feature slices

- **Status:** Partial
- **What's missing/incomplete:** Five concrete drifts from `.claude/rules/architecture.md`:
  1. `metric` has **no `dto.ts`** in `infrastructure/http/`; DTO mapping happens in `src/utils/mappers/metric.mapper.ts` (legacy `src/utils/` location).
  2. `metric` exposes **two transaction ports** (`PersistenceTransaction.ts` and `TransactionPort.ts`) — looks like a stalled refactor.
  3. `metric-log` has an `infrastructure/access/` directory (for `MetricAccessSequelize`) instead of `infrastructure/providers/`.
  4. `metric-settings` has both `infrastructure/mappers/` AND `infrastructure/persistence/` (other features keep mappers under `persistence/mappers/`); plus `infrastructure/providers/MetricAccessSequelize.ts` which **duplicates** the metric-log adapter for the same port contract.
  5. `analytics` has no domain entities and no repositories — only utility functions; uses raw SQL files (`infrastructure/sql/*.sql.ts`); schema file is named `validators.ts` instead of `schema.zod.ts`; query file `getMetricTrend.ts` is lowercase + plain function (other queries are PascalCase classes with `execute()`).
- **Why it matters for a SaaS base:** Forkers inherit ambiguity about the canonical pattern. Onboarding new contributors takes longer; ESLint cannot enforce a standard that has 5 exceptions.
- **Recommended fix:** Pick the canonical layout in `decisions.md`. Migrate slices to it (move metric mapper into `metric/infrastructure/persistence/mappers/`; delete duplicate `MetricAccessSequelize`; consolidate transaction ports; rename analytics `validators.ts` → `schema.zod.ts`; convert `getMetricTrend` to a class). Add an architecture-test (`__tests__/unit/architecture.test.ts`) that fails CI when a slice lacks the required dirs.
- **Effort:** M
- **Evidence:** `src/features/public/metric/` (no `dto.ts`); `…/metric/application/ports/PersistenceTransaction.ts` + `TransactionPort.ts`; `…/metric-log/infrastructure/access/MetricAccessSequelize.ts`; `…/metric-settings/infrastructure/providers/MetricAccessSequelize.ts`; `…/analytics/infrastructure/http/validators.ts`; `…/analytics/application/queries/getMetricTrend.ts`; `…/analytics/infrastructure/sql/*`.

### [P1] 10. Architecture · Sequelize types leaking into application layer

### [P1] 10. Architecture · Auth middleware re-implements `jwt.verify` outside the port
