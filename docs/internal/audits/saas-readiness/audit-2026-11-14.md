1. **Kit first.** The verdict rule (D-01), the method (D-02) and where a confirmation is recorded
   (D-03) were written and approved before a gate ran or a grader started. D-01 fixed in advance
   how a new P1 is treated, where the last run wrote that rule when its first P1 arrived.

3. **Four graders**, started after the install, reading the tree. Their usage limit stopped them

   lane was started afresh on another model (D-07).
4. **Reproduction of every ground that decides the verdict, of the six P2 fixes, and of the new
   P2 grounds that can be run**, by the main thread against the built evidence commit.
5. **A check of the cited lines** behind the verdict and every P2: each says what its grade claims.
6. **Fork dry-run** on four fresh clones (§5), and the **Appendix B scans**.

Every reproduction ran on throwaway services: `postgres:18`, `redis:7-alpine` and
`rabbitmq:3.13-management-alpine` on spare loopback ports, a stand-in mail sender with a fixed delay,
and a local listener in place of Sentry, with the built server and worker run from a scratch clone
and its own settings. The owner's `.env` files were never read. One deviation: `.env.test` points
the queue integration tests at `127.0.0.1:5672`, which on this machine is the owner's Compose
RabbitMQ, so the host test runs declared their test queues there. Nothing on it was deleted.
