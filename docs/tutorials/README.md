# Tutorials

Learning-oriented walkthroughs. A tutorial is followed start to finish by someone who has not done
the task before, and is expected to work **verbatim from a clean clone**.

|     |                                                           |                                                                          |
| --- | --------------------------------------------------------- | ------------------------------------------------------------------------ |
| 1   | [Getting started](./getting-started.md)                   | Clone → running API → authenticated request with real data. ~10 minutes. |
| 2   | [Your first feature slice](./your-first-feature-slice.md) | Read a slice end to end, then add an endpoint to it.                     |
| 3   | [Fork and rebrand](./fork-and-rebrand.md)                 | Make this template your own project.                                     |

Start with 1 even if you only need 3 — the fork script assumes a working local setup.

> Writing one? A tutorial teaches by doing and accepts no detours: no options, no alternatives, no
> explanation of _why_. Those belong in [`../how-to/`](../how-to/) and
> [`../explanation/`](../explanation/) respectively. If a step can fail for an interesting reason,
> say what the failure looks like rather than how to avoid it.
